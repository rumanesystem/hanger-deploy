1. 비유로 이해하기

지금 상황 = 큰 장부책 한 권

발주서 222건이 큰 장부책 한 권에 통째로 적혀 있어요.

📕 현재 (장부책 1권)

  • 발주서 1건 고치려면 → 장부책 통째로 가져가야 함
  • 두 사람이 동시에 가져가면 → 누구 게 최신인지 모름
  • 한 사람이 통째로 다시 갖다 놓을 때 → 다른 사람이 적은 거 지워짐
  • 그래서 발주서가 사라짐 (6/8 사고)

📑 변경 후 (낱장 카드)

  • 발주서 1건 = 카드 1장
  • 1건 고치려면 → 그 카드 1장만 꺼내면 됨
  • 두 사람이 다른 카드 동시에 꺼내도 → 충돌 없음
  • 발주서 사라질 일 없음

2. 지금 왜 자꾸 발주서가 사라지나

지금까지 발생한 일들:

날짜일어난 일
6/8발주서 3건 사라짐 (백업에서 복구)
6/9발주서 008 사라짐 (백업에서 복구)
6/11여러 안전장치 추가했지만 근본 원인은 그대로
핵심: 안전장치를 아무리 추가해도 "장부책 한 권" 구조 자체가 안 바뀌면 비슷한 사고가 또 일어날 수 있어요.

3. 어떻게 바꾸나

요약

모든 발주서를 한 곳에 몰아넣은 큰 장부책 → 발주서별로 따로 보관하는 카드함으로 바꾸는 거예요.

일하는 사람이 느끼는 변화

지금바뀐 뒤
발주서 사라지는 사고 가끔 발생거의 발생 안 함
발주서 동시 작업 시 충돌 위험각자 다른 카드라 충돌 없음
앱 로딩 시 222건 다 받아옴 → 느림필요한 만큼만 받아옴 → 빠름
화면·기능은 동일화면·기능은 동일
사용자(납품처, 관리자)는 화면이나 사용법이 바뀌는 게 없어요. 내부 저장 방식만 안전하게 바뀌는 거예요.

4. 어떤 순서로 진행하나

한 번에 다 바꾸면 위험해요. 단계별로 천천히, 매 단계 안전 확인하면서 진행합니다.

즉시

0단계: 가장 위험한 부분 먼저 고치기

⏱️ 1시간
출고확정 기능이 데이터를 "통째로 덮어쓰는" 부분 한 곳 → 안전한 방식으로 바꿈. 이것만으로도 사고 위험 크게 줄어요.
1단계

새 저장소 만들고, 양쪽에 동시 저장

⏱️ 4시간
옛 장부책에도 적고, 새 카드함에도 동시에 카드 만들어 넣음. 옛 저장소 그대로 두니까 위험 없음.
2단계

기존 발주서 222건을 새 카드함으로 복사

⏱️ 3시간
이미 있는 발주서들을 카드 1장씩 만들어 카드함에 넣음. 옛 장부책도 그대로 유지.
대기

1주일 검증

⏱️ 7일 모니터링
매일 자정에 자동으로 옛 장부책과 새 카드함을 비교. 차이 나면 즉시 알림. 1주일 동안 이상 없으면 다음 단계.
3단계

발주서 읽을 때 새 카드함 사용

⏱️ 6시간
읽기는 카드함에서, 쓰기는 일단 양쪽 다 (안전망). 이때부터 앱이 더 빨라짐.
4단계

옛 장부책 폐기

⏱️ 2시간
완전히 새 카드함만 사용. 옛 장부책은 30일 정도 보관했다가 백업으로 옮김. 끝!

5. 안전장치

🔘 즉시 차단 스위치

문제 생기면 관리자가 스위치 하나만 끄면 즉시 옛 방식으로 복귀해요. 코드 수정 안 해도 됨.

📊 자동 비교

매일 새벽 2시에 옛 장부책과 새 카드함을 자동으로 비교해요. 다른 게 발견되면 슬랙으로 즉시 알림 발송.

📦 30일 보관

옛 장부책은 바로 안 지우고 30일간 그대로 둠. 혹시 모를 사고 대비.

6. 위험은 없나

있어요. 솔직히 말씀드리면.

위험대응
옛 장부책과 새 카드함이 조금 다를 수 있음매일 자동 비교 + 알림
마이그레이션 중에 새 버그 가능각 단계 작게 나눠서, 매번 운영하며 확인
4단계 후 롤백은 비용 큼3단계까지는 1초 안에 롤백 가능. 4단계는 충분히 검증 후
2주간 신경 써야 함대신 끝나면 영원히 안심
