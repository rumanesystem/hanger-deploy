# 출고해야 할 품목 — "출고 현황" 화면 기획안 (확정본)

> 작성일 2026-06-01 · 기획팀(product-planner + ux-designer) 종합 · 사장 결정 반영
> **상태: 기획 확정. 코드 미작성.** 제작은 별도 지시 후 진행.

---

## 1. 한 줄 정의

발주서에 잡혀 있는 **출고일·출고창고·품목**을 자동으로 모아, 창고 직원이 폰으로 보며
"오늘 이 창고에서 무엇을 몇 개 꺼내야 하나"를 한 화면에서 확인·체크하는 **피킹 리스트 화면**.

## 2. 확정된 방향 (사장 결정)

| 항목 | 결정 | 의미 |
|---|---|---|
| 주 사용자 | **창고 직원 피킹용** | 품목 합산 테이블 중심, 모바일 한 손 조작 우선 |
| 체크 상태 저장 | **발주 상태로만 관리** | 품목별 임시 체크는 새로고침 시 풀림. `출고완료` 버튼만 서버 저장 |
| 진행 범위 | **기획 확정만** | 본 문서가 산출물. 제작은 추후 지시 |

## 3. 화면 방식 (확정: 독립 화면 + 창고탭+품목합산)

- **진입점**: 사이드바에 신규 메뉴 **"출고 현황"** 추가
- **레이아웃**:

```
┌──────────────────────────────┐
│  출고 현황                     │
│  [시흥]  [평택]      ← 창고 탭   │
│  [오늘] [내일] [이번주] ← 날짜   │
├──────────────────────────────┤
│  품목         수량    완료      │
│  옷봉         45개    □ 전체     │
│  상부자재 L   2세트   □ 전체     │
│  서랍장 3단   3개     □ 전체     │
│  선반         8장     □ 전체     │
│  [상세 발주 목록 보기 ↓]         │
└──────────────────────────────┘
```

- 같은 품목은 여러 발주서에 흩어져 있어도 **합산해서 한 줄**로 표시 (창고 피킹 동선과 일치)
- 옷봉은 **절단규격(mm)별로 합산** 표시
- "상세 발주 목록 보기"로 펼치면 어느 납품처 출고분인지 확인 가능

## 4. 데이터 출처

- 기존 발주서(order)를 **읽기만** 한다. 데이터 구조 변경·신규 컬렉션 없음.
- 대상: 상태가 `발주확정` 또는 `출고준비`이고, 선택한 창고/날짜에 해당하는 발주서.
- 출고일 `미정` 건은 별도 "미정" 묶음으로 표시.

## 5. 상태 흐름 연결 (기존 그대로 유지)

```
임시저장 → 발주대기 → 발주확정 → 출고준비 → 출고완료
                          └─ 출고 현황 화면이 읽는 구간 ─┘
```

- 화면에서 품목별 체크는 **눈으로 진행 확인용(임시, 미저장)**.
- 발주서 단위 **"출고완료"** 버튼을 누르면 → 상태를 `출고완료`로 전환(서버 저장).
- `nextStatuses()` 등 기존 상태 로직은 **변경하지 않음**.

## 6. 기능 우선순위

**MVP (P0)**
- 사이드바 "출고 현황" 메뉴 + 화면
- 창고 탭(시흥/평택) + 날짜 필터(오늘/내일/이번주)
- 구역별 품목 합산 테이블 (옷봉 절단규격 합산 포함)
- 발주서 단위 `출고완료` 전환 버튼
- 상세 발주 목록 펼침(아코디언)

**P1 (2차)**
- 대시보드 소형 위젯("오늘 출고 시흥 3건 / 평택 1건" → 바로가기)
- 인쇄/공유(창고 직원 종이 출력)

**P2 (나중)**
- 납품처별 필터
- 출고 캘린더 뷰

## 7. 제작 시 확인할 선행 사항 (제작 단계에서 검증)

- **품목 합산 가능 여부**: 발주서 품목이 코드/드롭다운 기반이면 합산이 깔끔. 자유 텍스트 비중이 크면 합산 정확도 확인 필요 → 제작 전 `orders.js`/`order-modal.js` 데이터 형태 점검.
- 합산이 어려운 항목은 차선책으로 "납품처별 카드"로 표시 보완.
